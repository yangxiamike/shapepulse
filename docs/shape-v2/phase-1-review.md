## 🧩 V1 现状与影响面

V1 是一套共享入口下的三段手写规则：

| 层 | 当前依赖 |
|---|---|
| 规则 | `server/patterns.py` 固定 `breakout / pullback / range_bounce`，各自有阈值和手写分数 |
| 配置 | `config/thresholds.json`，规则版本为 `1` |
| 筛选 | `server/service.py` 同时生成综合榜、三类独立榜和形态详情 |
| 历史 | SQLite 保存类别键、类别名、分数、理由、规则版本和整次响应 |
| API | `/api/screen`、`/api/pattern/pool`、`/api/pattern/{code}`、`/api/industry-strength` 都依赖旧键 |
| 前端 | TypeScript 联合类型、看板、行情页、行业强弱页均写死旧三类 |
| 测试/文档 | 后端单测、页面测试、验收脚本和 V1.2 API 文档都引用 `range_bounce` |

因此，旧“区间下沿反弹”不能直接改名或删除。V2 验证通过前，V1 契约必须冻结。

## 🧪 匿名样本与切分骨架

### 公开评审包

只包含：

- 匿名编号。
- T-119 到 T0 的 120 根归一化 OHLCV。
- 三类空白 0～3 标签。
- 无身份的共用事实向量。

明确不包含：

- 股票名称、代码、行业。
- 真实交易日期、评分日期。
- T0 之后的 K 线或任何未来收益字段。

### 私密审计映射

真实代码、评分日、原始交易日序列、数据快照和公开文件哈希只保存在：

`outputs/shape-v2/.private/`

该目录位于仓库既有 `/outputs/` 忽略范围内，不进入版本控制，也不进入评审包。

### 泄漏防护

1. 查询在评分日截断，随后再次过滤 `trade_date <= score_date`。
2. 每个样本必须恰好有 120 根历史 K 线，最后一根为 T0。
3. 复权只使用评分日及以前的复权因子。
4. 切分以整只股票为最小分组；同一股票的所有日期只能进入一个集合。
5. 校准集与模板/调优/最终评估集隔离。
6. 最终评估集一旦封存，不参与权重、门槛、矛盾条件或特征选择。
7. 若根据最终评估集错误继续修改模型，该集合立即降级为调优集，并重新封存新的最终评估集。
8. 自动审计检查跨集合股票、重复样本、日期越界、公开字段泄漏和内容哈希。

研究集默认按股票组稳定切分：

- 模板样本 50%。
- 调优样本 25%。
- 最终评估样本 25%。

比例是第一版建议，定义确认后可在第一次正式切分前调整；一旦生成封存集便不再改动。

## 🧱 共用事实底座与三套评分器

已实现的共用事实底座只计算评分日当下可见事实，例如：

- 3/5/10/20/60/119 日涨跌。
- 10/20/60/120 日趋势斜率与拟合度。
- 均线乖离和均线排列。
- 突破幅度、区间位置、回撤、距高点天数。
- 波动、ATR、上涨日比例。
- 近期量比、涨跌日量能对比。
- 回调后的短线反弹和收盘位置。

三类拥有各自独立因子列表和核心矛盾。权重、统计模板、软评分函数和达标门槛尚未填写，避免在定义确认前把草案误当正式模型。

第一版评分流程拟定为：

1. 从每类高相关模板样本形成中位数、四分位区间和稳健尺度。
2. 对该类自己的因子向量做稳健标准化。
3. 使用可解释的加权欧氏距离计算相似度。
4. 应用少量核心矛盾限制和最低门槛。
5. 每类独立排序，不强迫三类互斥。
6. 样本足够后，才在同一个未参与调参的测试集上对比马氏距离。

## 📊 后续评估口径

只评估当前形态检索和排序：

- Top20 / Top50 纯度。
- 严重错误率（0 分或触发核心矛盾的前排样本）。
- NDCG（0～3 相关度）。
- 两两排序准确率。
- 类别混淆。
- 分数分层表现。

不计算未来收益、IC 或任何交易策略指标。

## 👀 下一评审关口

请先评审 `category-definition-cards.md`，重点拍板：

1. 三类定义和核心矛盾是否准确。
2. 是否允许同一样本同时属于多类。
3. 三个边界问题：突破后宽限天数、健康趋势对 20 日均线跌破的容忍、回调转强的最低确认信号。
4. 0～3 标注尺度是否可直接用于模板、调优和最终评估。
5. 120 日窗口、价格首日归一为 100、成交量中位数归一为 1 是否确认。
6. 首次正式切分的 50% / 25% / 25% 比例是否确认。

定义确认后进入“匿名样本校准”。此后才会构建基准版排名和错误样本报告。
