## 2. 核心修复

### 看板、形态与字体

- 修复 Top 50、顶部统计、状态文案、详情操作区和大号数字行盒的越界或裁切。
- 综合筛选不再剔除 `matches`；前端类型、API 映射、候选表、选中状态和详情水合全链路保留全部真实匹配。
- 当真实事实只有一个时明确显示“仅匹配 1 个真实形态”；多结果显示“共匹配 N 个真实形态”。
- 新增侧栏“小 / 标 / 大”字号入口，使用本地存储持久化；图表坐标文字同步变化。
- 右侧详情改为零最小宽度网格，避免比例拖窄后形态分数和指标事实被容器裁掉。
- 行情页“形态股票列表”不再被最近一次保存的窄快照或 500 只旧上限截断，改为始终显示当前本地筛选的完整真实分类池；2026-07-16 快照下三类分别为 158、151、2444 只。
- 看板小图默认展示近 3 个月（66 根），最新 K 线后保留 8 根逻辑空位；每次切换股票都会重建视窗，避免沿用上一只股票被拖动或缩放后的排布。

### 划线与斐波那契

- 趋势线、线段、射线、斐波那契、曲线和测量采用可靠的两点点击流程。
- 线段只位于两锚点之间；射线从第一点穿过第二点向前延伸；趋势线贯穿画布两侧。
- 自动化实测边界：
  - 趋势线：`x=0…1031`
  - 线段：`x=254…695`
  - 射线：`x=254…1031`
- 斐波那契设置即时作用于当前图形，并作为后续同类图形默认值；默认项只能开关，自定义项可删除。
- 新增矩形工具：第一次点击确定一个对角点，移动时实时预览，第二次点击完成；支持边线或框内命中、端点调整和整框拖动。

### 分隔拖动

- “自由调整”在桌面同时接受左右和上下变化，并显示实时宽度比例与高度。
- “仅左右比例”只改变候选/详情宽度，不改变工作区高度。
- 1024 窄屏时，自由模式改为真正的上下分隔；仅左右模式隐藏无意义的分隔器。
- 指针和键盘均受合理 min/max 限制。

## 3. 主动发现并继续修复的问题

编码后没有停在测试通过，逐张检查截图又发现并修复：

1. 个股详情接口水合时用 `undefined` 覆盖了候选行的多形态 `matches`，导致计数先显示 2、异步后回落为 1。
2. 详情卡的隐式 CSS Grid 列按内容最小宽度撑大，比例模式拖窄后分数和指标右侧被裁切。
3. 字体本地存储在 hydration 前写入根节点时产生 React 警告，已明确抑制该预期根属性差异。
4. 早期截图只等容器出现，行情画布尚未绘制；现改为检查真实彩色画布像素后才截图。
5. 旧版验收在 Windows 偶发固定截图文件瞬时占用，增加一次有边界的重试，避免非产品故障使整套回归中断。
6. 形态列表错误优先读取最近保存的窄筛选快照，导致完整 158 只真实结果被压成 1 只；现已移除该错误优先级，并增加后端回归断言。
7. 两条 V1.1 旧验收仍写死看板 110 根（5 个月），与本次明确的 66 根（3 个月）需求冲突；已同步为新口径后全量回归通过。

## 6. 真实遗留风险

- 本地数据服务进程首次读取未缓存股票时，受磁盘和 DuckDB 冷启动影响，可能超过旧 2 秒预算；热缓存与后续切换均在预算内。
- 表格在 1600 大字体、1366 和 1024 下保留内部横向滚动，这是为了不丢失 10 列语义；页面本身没有横向溢出。
- 绘图仍是页面会话状态，刷新后不持久化；本次范围没有要求图形存储。
- 仅验收本机 Chrome，事实结论受本地 2026-07-16 快照限制。
- 该产品依赖本机 `zer0share` 与本地后端，未部署为公网站点；部署会破坏“仅本机数据源”的边界。
