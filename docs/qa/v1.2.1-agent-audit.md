## 1. 结论

V1.2 的基础行情、十类绘图创建、代表性端点拖动、形态列表滚轮、1024 右侧抽屉开合、三档页面无全局横向溢出均可用；但 V1.2.1 所关注的交互问题确实存在，且不是偶发问题：

1. **行情图原生交互被绘图遮罩稳定拦截。** 默认状态就是 `select`，整张透明画布始终接管指针事件，十字光标、图表拖动和平滑滚轮缩放都没有传入 lightweight-charts。
2. **曲线命中区域与可见曲线不一致。** 点击可见的贝塞尔曲线中段不会选中，点击曲线下方不可见的直线弦反而会选中。
3. **1366/1024 看板详情操作区被裁切。** “待判断”和“打开行情”只有约 33% 高度露出；控件几何中心落在卡片外，普通居中点击命中 `main`，不是按钮。
4. **形态列表键盘能切股，但不会跟随活动项滚动。** 第 5 项起活动项已经完全跑出 224px 高的可视区，`scrollTop` 仍为 0。
5. **桌面右栏折叠、右栏分隔拖动和看板分隔拖动均不存在。** 当前只有静态边框和固定栅格；1024 的移动抽屉开合正常。
6. **绘图样式没有产品能力。** 颜色、线宽、文本内容均无状态字段和控件；未选中统一黑色、选中统一蓝色，文本恒为“文本标记”，测量值是像素而非时间/价格。

建议将前 4 项作为阻断交互验收的问题；右栏/看板分隔和样式能力如果属于 V1.2.1 明确需求，也应作为同级阻断项。

## 4. 详细问题与真实原因

### F1. 行情图原生控件和手势被绘图遮罩拦截

**严重度：P1 / 阻断**

复现：

1. 打开 `/market?code=002747`。
2. 保持默认“选择/调整”模式。
3. 在蜡烛图区域移动鼠标，观察十字光标。
4. 在图表中心滚轮缩放。
5. 按住鼠标水平拖动。

实际：

- 遮罩画布计算样式为 `pointer-events: auto`，`data-drawing-mode=select`。
- `elementFromPoint()` 在图表中心返回 `canvas.drawing-overlay.drawing`。
- 鼠标移动、滚轮和拖动前后，底层 7 张 lightweight-charts canvas 的 `toDataURL()` 均未改变。
- 十字光标按钮本身能切换状态，但鼠标移动没有到达底层图表，用户看不到有效反馈。

DOM/CSS/事件原因：

- `MarketClient.tsx:70` 把 `drawingMode` 初始值设为 `"select"`。
- `MarketChart.tsx:642` 用 `Boolean(drawingMode)` 判定整个遮罩是否交互；`"select"` 为真。
- `MarketChart.tsx:654-664` 的遮罩覆盖完整图表并绑定全部 pointer 事件。
- `globals.css:338-339` 令 `.drawing-overlay.drawing` 接管指针。
- `MarketChart.tsx:542-556` 在 select 模式自行处理并直接返回；没有把未命中画线的事件交还给底层图表。

建议：

- 将“画线选择命中”与“图表原生交互”分开。未命中绘图时，应进入图表 pan/zoom/crosshair，而不是让全屏遮罩吞掉事件。
- 不要只切 `pointer-events:none` 后依赖遮罩接收命中；可使用显式“图表导航/画线编辑”模式，或把绘图 hit-test 接到同一事件入口后转发/桥接给 chart。
- 自动化必须断言 logical range 和 crosshair 状态变化，不能只断言按钮 `aria-pressed`。

### F2. 曲线绘制轮廓与命中模型不同

**严重度：P1 / 阻断**

复现：

1. 清空画线，选择“曲线”。
2. 从相同高度的 `(250,300)` 拖到 `(650,300)`。
3. 点击可见曲线中点约 `(450,268)`。
4. 再点击不可见弦线中点 `(450,300)`。

实际：

- 点击可见曲线：`删除所选 aria-pressed=false`。
- 点击不可见弦线：`删除所选 aria-pressed=true`。

源码原因：

- `MarketChart.tsx:290-296` 用二次贝塞尔曲线绘制。
- `MarketChart.tsx:236-257` 的 `hitDrawing()` 只特殊处理自由绘制、斐波那契和文本。
- 曲线最终落入 `lineEndpoints()` + `distanceToSegment()`，按端点直线判断，不按贝塞尔轮廓判断。
- `MarketChart.tsx:320-323` 只显示起点/终点把手，没有曲线控制点。

建议：

- 用贝塞尔采样折线或解析距离做 hit-test。
- 把控制点写入 drawing 模型，选中曲线时显示第三把手，并允许拖动。
- 自动化采用同高端点构造固定曲线，分别断言“可见曲线命中、弦线空白不命中”。

**严重度：P1**

滚轮实测：

- 当前池 151 个按钮。
- 容器 `clientHeight=224`、`scrollHeight=7556`。
- 在列表上滚轮后 `scrollTop: 0 → 640`，滚轮功能通过。

连续键盘实测：

| 1 | 53-103 | 0 | 是 |

| 5 | 253-303 | 0 | 否 |

源码原因：

- `MarketClient.tsx:164-178` 在 `window` 上处理上下键，计算下一个索引并调用 `loadStock()`。
- `MarketClient.tsx:326-327` 只根据当前 code 设置 `active/aria-current`，没有活动按钮 ref、`scrollIntoView()` 或 roving tabindex。
- 151 个按钮全部保留在 tab 顺序中，长列表键盘穿越成本高。
- 键盘切股依赖 `drawingMode === "select"`；用户刚选择某个画图工具但尚未落笔时，上下键会突然失效。

- 首次进入 `?category=pullback` 时，下拉框为 pullback，但 URL 被改写为 `category=breakout`。`MarketClient.tsx:125-126` 的 `loadStock()` 使用旧闭包中的 `patternCategory`，而 `MarketClient.tsx:140-143` 在同一启动回调中先 setState 再调用旧的 `loadStock()`。

建议：

- 活动项改变后执行最小滚动，保证完整落在容器可视区。
- 使用 roving tabindex：活动项 `tabIndex=0`，其他项 `-1`。
- 将形态切股快捷键与绘图模式冲突写成明确规则；至少不要静默失效。
- 修正首次 URL 分类写回，增加深链刷新断言。

## 5. 三档可读性与视觉风险

### 1600×1000

通过：

- 行情主区 1104px、右栏 360px，摘要无字段裁切。
- 绘图工具 15 个全部落在 551px 高的工具区内。
- 看板两列，详情按钮完整可见。
- 页面无全局横向溢出。

## 6. 性能结论与风险

暖缓存实测页面反馈：

- 行情：`总 197ms · HTTP 168ms · 查询 61ms · 绘制 66ms`
- 看板：`完成 · 3041 只进入股票池 · 180ms · 已命中缓存`
- 形态上下键连续切股：5 次为 `157/159/127/121/151ms`，平均约 143ms。

这些暖缓存结果可接受，但存在以下结构性风险：

1. **绘图每个 pointermove 重置整张 canvas。** 基线 `paintDrawings()` 每次都重新赋值 `canvas.width/height`，会重新分配位图；高 DPI、4 图、自由绘制时成本放大。
2. **自由绘制按每个移动事件复制 points 数组。** `points=[...points,current]` 随路径增长持续分配，长笔迹近似二次复制成本。
3. **多图重复渲染全历史。** 1/2/4 图都接收相同 2694 根完整 bars 和相同 drawings；每次父状态更新会触发多个实例同步绘制。
4. **键盘快速连按没有取消请求。** `loadSequence` 只丢弃旧响应，不会 Abort 已发出的 stock/bars/pattern 请求，连续按键仍可能堆积本地查询。
5. **形态池无虚拟化。** API 请求上限 500，当前 151 个按钮全部渲染；当前 7556px 内容尚可，但上限状态会增加布局、tab 顺序和切股更新成本。
6. **现有性能数字容易被缓存掩盖。** 建议分开记录首次打开、后端缓存、前端缓存和连续切股，而不是只读最后一次 perf chip。

## 7. 现有自动化为何漏检

`tests/e2e/v1.2-acceptance.spec.ts` 当前覆盖了基础能力，但断言不足以捕获本次问题：

- `72-79`：只点一次形态列表和一次 `ArrowDown`，没有连续走出可视区，也没有检查 `scrollTop`。
- `94-110`：只绘制斐波那契并比较 canvas 数据变化，再删除；没有验证其他工具几何、端点坐标、曲线命中、颜色/线宽或图表原生手势。
- `115-140`：只检查全局横向溢出、侧栏几何和候选区/状态卡不重叠；没有检查详情按钮与 clipping ancestor 的可见交集。

- 截图包含问题，但测试没有把可见性转换成几何断言。

## 8. 建议的 Playwright 定位与断言

### 8.1 优先使用的现有定位

- 搜索：`getByRole("textbox", { name: "搜索股票" })`
- 右栏标签：`getByRole("button", { name: "形态", exact: true })`
- 形态分组：`getByTestId("pattern-group-select")`
- 形态池：`getByTestId("pattern-pool")`
- 当前形态股票：`pool.locator('button[aria-current="true"]')`
- 绘图工具：`getByRole("button", { name: "线段", exact: true })`
- 绘图画布：`locator("canvas.drawing-overlay").first()`
- 移动右栏：`getByRole("button", { name: "打开右侧面板" })`
- 看板操作：`getByRole("button", { name: "待判断", exact: true })`、`getByRole("link", { name: "打开行情" })`

### 8.2 建议新增的稳定定位

- 行情交互面：`data-testid="market-chart-interaction"`
- 图表可视范围：在 `.market-chart` 暴露 `data-logical-from/to`，由 visible logical range 订阅更新。
- 绘图状态：暴露 `data-drawing-count`、`data-selected-drawing-index`；测试环境可额外暴露选中 drawing 的归一化端点。
- 右栏折叠按钮：`aria-label="收起右侧面板"` / `"展开右侧面板"`
- 右栏分隔线：`role="separator"` + `data-testid="market-right-separator"`
- 看板分隔线：`role="separator"` + `data-testid="board-detail-separator"`
- 样式：`getByLabel("画线颜色")`、`getByLabel("画线粗细")`、`getByLabel("文本内容")`

### 8.3 必加断言

1. **图表原生交互**
   - select 模式下在空白区域移动、滚轮、拖动。
   - 分别断言 crosshair 出现、logical range 缩放、logical range 平移。

2. **端点和曲线**
   - 固定相对坐标画线段，拖起点后断言归一化 `x1/y1` 改变、`x2/y2` 不变。
   - 同高端点画曲线，点击贝塞尔可见中点应选中，点击弦线空白不应选中。
   - 拖曲线控制点后断言 control 改变。

3. **形态列表**
   - 连续 8 次 `ArrowDown`。
   - 每一步断言活动项 `rect.top >= pool.top` 且 `rect.bottom <= pool.bottom`。
   - 断言第 5 项前后 `scrollTop` 增加。
   - 单独在列表中心滚轮，断言 `scrollTop` 增加。

4. **详情按钮裁切**
   - 对按钮与每个 overflow 非 visible 的祖先计算交集。
   - 要求最终可见比例为 1，且按钮中心 `elementFromPoint()` 命中自身或后代。

5. **分隔线**
   - 以 `role=separator` 定位，拖动 80px。
   - 断言左右面板宽度按预期变化，合计宽度守恒，图表 canvas 尺寸同步变化。
   - 键盘 `ArrowLeft/ArrowRight` 也应改变 `aria-valuenow`。

6. **三档回归**
   - 保留 `1600/1366/1024` 循环。
   - 增加空白按钮检测：可见按钮必须有可见文本、图标或明确图形。
   - 增加绘图工具首尾按钮可达断言。
   - 保留全局无横向溢出与状态卡不重叠断言。

## 10. 验收建议

V1.2.1 不应只以“按钮能点、canvas 有像素变化、页面没有横向滚动”作为通过条件。最低可接受门槛应为：

- 图表导航与绘图编辑不互相吞事件。
- 曲线可按所见轮廓选中并调整控制点。
- 连续键盘切股时活动项始终可见。
- 1366/1024 的详情操作按钮完整可见。
- 桌面右栏与看板分隔能力有明确 DOM、键盘和鼠标语义。
- 样式能力若纳入 V1.2.1，必须持久存在于 drawing 模型，而不只是临时改 canvas 颜色。
