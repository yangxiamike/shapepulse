# v1.1 最终验收报告规划

最终报告路径：`docs/qa/v1.1-acceptance.md`

证据根目录：`docs/qa/screenshots/v1.1/`、`docs/qa/evidence/v1.1/`

## 报告结构

1. 结论：通过/失败、验收日期、分支、提交、数据快照。
2. 环境：Windows、Chrome、视口、前后端地址、zer0share 绝对路径。
3. 构建与测试：命令、通过数、失败数、耗时。
4. 功能验收：看板、行情、信息架构、状态持久化。
5. 周期聚合校验：每周期样本边界和 OHLCV 对账。
6. 性能：首次、重复、同股票、换股后四组；前端/HTTP/查询/绘制拆分。
7. 三档浏览器验收：1600×1000、1280×900、1024×800。
8. 视觉验收：三类各 5 只、候选表、预览 K 线、成交量、形态解读、字体和坐标。
9. 缺陷记录：步骤、实际、预期、严重度、修复/残留、截图。
10. 对批准概念图的差异与保留理由。
11. 数据源审计：请求域名与后端 source 证明仅使用本地 zer0share。
12. Git 与回滚：提交列表、主分支未改、回滚方法。
13. 残余风险与是否具备发布条件。

## 浏览器逐项步骤

1. 打开看板，等待首轮筛选完成，记录进度和耗时。
2. 用鼠标和键盘分别进入三类榜，展开完整结果并滚动到末尾。
3. 每类选择至少 5 只，检查表格、预览、成交量、理由和指标并截图。
4. 测试保存、取消保存、待判断、取消待判断、已查看和历史。
5. 从看板打开行情，核对默认 95–115 根日 K 和 2 秒首屏预算。
6. 切换周/月/季/年，重复周期，记录缓存和详情请求数。
7. 操作范围、缩放、拖动、十字光标、趋势线、水平线、文本、测量和清除。
8. 搜索并换股，测试键盘联想、错误重试、自选添加/移除和刷新保持。
9. 打开详情、形态、指标、因子、交易，核对事实、空状态和禁用说明。
10. 在三档视口重复关键流程，检查溢出、遮挡、焦点和右栏入口。
11. 查看控制台、网络请求和源地址，记录 hydration、运行时错误与外部请求。
12. 若任一项失败，保存失败截图，修复后按同一步骤复测并保存修复截图。

## 报告结论规则

- 有 P0/P1、性能硬指标失败、三类抽样不足或任一视口核心流程失败：结论为失败，继续迭代。
- 仅有已披露的 P3 且全部硬指标通过：可结论通过，并列残余风险。
- P2 是否允许残留需明确说明替代路径，并在最终汇报中等待用户判断。
