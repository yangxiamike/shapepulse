# 手动跟踪市场 v1.1 性能预算

日期：2026-07-16

测量环境：本机 Chrome、前端 `127.0.0.1:3000`、后端 `127.0.0.1:8765`、本机 zer0share 快照。

## 1. 硬指标

| 场景 | 起点 | 终点 | 预算 |
|---|---|---|---:|
| 按钮视觉反馈 | `pointerdown` | 按压/加载态绘制 | ≤100ms |
| 搜索联想 | 输入事件 | 结果列表绘制 | ≤300ms |
| 已缓存 K 线周期切换 | 点击周期 | 新周期图表绘制 | ≤300ms |
| 首次未缓存周期切换 | 点击周期 | 新周期图表绘制 | ≤700ms |
| 换股并显示行情 | 选择结果/自选 | 报价与 K 线绘制 | ≤1000ms |
| 看板打开行情首屏 | 点击“打开行情” | 报价与默认 K 线可读 | ≤2000ms |
| 常用筛选（缓存或增量） | 点击运行 | 候选表与摘要绘制 | ≤1000ms |
| 首次全市场重计算 | 点击运行 | 完整结果绘制 | ≤3000ms |

首次全市场计算若 1 秒内未完成，必须已显示真实阶段与进度，不得只有静态转圈。

## 2. 性能设计约束

- 股票详情缓存键：股票代码；周期切换不得重复请求详情。
- K 线缓存键：股票代码 + 周期 + 范围 + 复权方式 + 数据日期。
- 重复周期切换直接复用前端缓存；后端也保留查询缓存并回报 `cache_hit`。
- 当前股票的详情和默认 K 线优先；自选列表异步加载，不进入首屏关键路径。
- 图表实例尽量复用，只更新 series 数据和可见范围；必须重建时记录绘制耗时。
- 筛选结果缓存键包含各相关表日期、阈值版本和筛选参数。
- HTTP 返回 `Server-Timing` 或 JSON timings，至少区分解析/查询/评分/序列化。

## 3. 必测四组

| 组别 | 操作 | 需记录字段 |
|---|---|---|
| 首次 | 冷启动打开默认股票并首次切周 K | 前端总耗时、HTTP、后端查询、图表绘制、缓存命中 |
| 重复 | 周 K → 日 K → 周 K | 同上；第二次周 K 必须命中缓存 |
| 同股票 | 连续切日/月/季/年 | 详情请求次数、每周期总耗时、bars 请求次数 |
| 换股后 | 搜索并打开另一只股票，再切已访问周期 | 搜索、换股首屏、详情、bars、图表绘制 |

同时记录：

- 看板首次筛选与重复筛选。
- 从看板点击“打开行情”到行情首屏。
- 1600、1280、1024 三档视口至少各一组交互数据。

## 4. 采集方式

- 浏览器：`performance.mark/measure`、Resource Timing、Playwright 事件时间戳。
- HTTP：响应总时长、响应体中的后端 timings 与 cache 标志。
- 后端：`perf_counter` 分段记录数据读取、股票池过滤、形态评分、历史写入。
- 图表：从设置 bars 到下一次 `requestAnimationFrame` 后的稳定绘制。
- 每个关键场景至少测 3 次，报告中同时给出首次值和重复中位数，不用理论估计替代实测。

## 5. 失败处理

- 任一硬指标超预算即失败，先定位到前端、HTTP、查询或绘制阶段再修复。
- 环境抖动可重测，但不得删除不利结果；报告记录异常原因与最终复测证据。
- 首次全市场筛选超过 3 秒时，必须继续优化；不能只靠进度条通过。
