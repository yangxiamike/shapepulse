# 手动跟踪市场 v1.1 需求说明

状态：文档基线

日期：2026-07-16

目标分支：`codex/v1.1`

## 1. 目标

v1.1 在不改变本地、手工复核定位的前提下，把现有原型补齐为可真实使用、可解释、可验收的本地 A 股工作台：

- 综合选股看板提供三类形态各自独立的 Top 50、完整结果查看和可追溯的人工状态。
- 本地行情终端提供正确的多周期 K 线、可用的基础画线工具、持久自选和当前股票的形态事实。
- 两页保持解耦，只共享股票代码、形态事实和跳转入口。
- 只读取 `C:\Users\hp\Documents\zer0share` 已同步的本地 Parquet/DuckDB 快照。
- 在 1600×1000、1280×900、1024×800 三档真实 Chrome 视口达到功能、视觉和性能验收线。

## 2. 数据源与数据口径

### 2.1 唯一数据源

- zer0share 根目录：`C:\Users\hp\Documents\zer0share`
- 配置：`C:\Users\hp\Documents\zer0share\config\settings.toml`
- 允许读取的本地接口：`stock_basic`、`daily`、`daily_basic`、`adj_factor`、`stock_st`、`index_member_all`。
- 状态和形态历史写入项目本地 SQLite；不把它当成行情源。
- 禁止使用在线 Tushare、浏览器第三方接口、公共行情 API、模拟报价或外部回退源。

### 2.2 日期口径

页面分别显示：

- 行情日期：`daily_kline` 最新可用分区。
- 估值日期：`daily_basic` 最新可用分区。
- ST 日期：`stock_st` 最新可用分区。
- 复权日期：`adj_factor` 最新可用分区。

各日期不能合并成一个含混的“数据日期”。日期不同、缺估值、ST/复权滞后时必须给出可见警告。空 ST 分区不能被解释成“没有 ST”。

zer0share 配置中的 `data_dir` 是相对路径，后端必须相对 zer0share 根目录解析为绝对路径，不能受服务启动目录影响。

### 2.3 K 线与聚合

- 默认日 K：最近约 5 个月，使用最后 110 个交易日；允许范围切换扩展或收缩。
- 日 K：原始交易日 OHLCV。
- 周 K：按自然交易周聚合，开盘取首日、最高取最大、最低取最小、收盘取末日、成交量/额求和。
- 月 K：按自然月聚合，语义同上。
- 季 K：按自然季度聚合，不能映射成月 K。
- 年 K：按自然年聚合，不能映射成月 K。
- 默认前复权；若因子缺失或滞后，显示真实警告，禁止静默伪造。

### 2.4 形态事实

- 三类：`breakout`（突破启动）、`pullback`（上升趋势回调）、`range_bounce`（区间下沿反弹）。
- 每一类独立计算、排序并保留 Top 50；综合榜是跨类别总分 Top 50，二者不能混用。
- 当前匹配事实包含：名称、是否匹配、分数、识别日期、理由、关键指标、阈值、规则版本、行情/估值/ST/复权日期、警告。
- 形态历史来自真实筛选历史；“较昨日”只在存在前一交易日可比记录时计算，否则显示“暂无对比”。
- 空状态区分“尚未计算”和“已计算但无匹配”。

## 3. 功能范围

### 3.1 综合选股看板

1. 三张形态概览卡可点击、可 Tab 聚焦、可用 Enter/Space 进入各自分类榜。
2. 每类榜均显示独立排名与最多 50 只；综合榜单独显示综合排名。
3. “查看全部 50 只”展开完整结果，采用分页或可滚动区域，不能只改文案。
4. 候选表展示类别、类别排名/综合排名、理由、分数、市值、涨跌幅和短期走势。
5. 右侧预览在 ≥1440 时有效绘图区不低于 420×280；≤1366 改为上下布局，不缩小到不可读。
6. 详情区展示形态理由和关键指标，不使用无数据支撑的默认理由。
7. 提供真实空状态、错误状态、重试、筛选进度与完成反馈。
8. 已查看、已保存、待判断、历史记录可打开具体条目；保存和待判断支持添加/移除。
9. 从候选进入行情页时携带股票代码；形态页不把行情终端变成推荐流。

### 3.2 本地行情终端

1. 从 URL 或搜索切换股票，首屏默认 110 根日 K 左右。
2. 日/周/月/季/年 K 具有不同、正确的聚合结果。
3. 范围选择能改变可见或请求范围；缩放、十字光标、趋势线、水平线、文本、测量、清除画线可操作。
4. 未实现的分时、分钟线、指标、对比、预警、回放、多图布局、布局保存、因子与交易必须禁用并说明。
5. 右栏含“自选、详情、形态、指标、因子、交易”六个并列标签。
6. “形态”只展示当前股票的事实与历史，并只提供“到选股看板查看该股记录”的跳转。
7. 自选完全以本地 SQLite 为准；默认示例列表不能重新注入，股票可真实移除并跨刷新保持。
8. 详情展示基础资料、估值、行情与各表日期，不保留空泛占位。
9. 错误状态提供重试；服务端渲染和客户端首帧一致，消除 hydration mismatch。
10. 1280/1024 不得因图表固定宽度裁切；1024 使用可打开的右栏抽屉或底部面板。

### 3.3 信息架构

- 主导航只保留一个行情入口，名称统一为“本地行情”。
- 看板负责筛选、排名、人工复核和筛选历史。
- 行情页负责当前股票行情、资料、自选、形态事实与通用分析工具。
- 禁止在行情页出现 Top 50、今日推荐、筛选进度、上一只/下一只等推荐流程。

## 4. 性能范围

必须满足 `performance-budget.md`。重点约束：

- 周期数据按股票、周期、范围、复权方式缓存；重复切换不重复请求。
- 同股票周期切换不重复请求股票详情。
- 自选加载不能阻塞当前股票首屏。
- 首次筛选若超过 1 秒立即显示真实阶段进度，3 秒为上限。
- 记录首次、重复、同股票、换股后四组前端/HTTP/后端查询/图表重绘耗时。

## 5. 非目标

- 不新增或同步 zer0share 数据。
- 不接实时行情、分钟行情、新闻、公告、财务报表、基金、港股、美股或交易接口。
- 不实现自动下单、策略回测、盘中预警和推荐推送。
- 不修改三类形态的投资含义；阈值只能版本化调整并在报告中说明。
- 不推送远端、不发布、不部署。

## 6. 依赖

- Python/uv 与本机 zer0share 环境。
- Node.js、pnpm、vinext、React、lightweight-charts。
- 本地 Chrome 与 Playwright，用于真实浏览器验收。
- 本地数据分区必须存在；缺表时产品显示错误和同步提示，但本任务不擅自同步。

## 7. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 表日期不同 | 误判 ST、估值或复权状态 | 独立日期字段与警告，验收滞后场景 |
| 全市场逐股 Python 评分过慢 | 超过 3 秒 | 缓存基础池与评分结果，分阶段计时，必要时优化向量化/预计算 |
| 分类结果不足 50 | “Top 50”误导 | 显示“共 N 只”，保持真实数量，不填充其他类别 |
| 图表重建成本高 | 周期切换卡顿 | 缓存 bars，复用详情，记录 chart render 时间 |
| 小视口信息密度过高 | 裁切或不可操作 | ≤1366 上下布局；1024 右栏抽屉；表格允许受控横向滚动 |
| 历史样本不足 | 无法计算昨日对比 | 明示“暂无对比”，不使用固定示例数值 |
| 本地状态库已有用户数据 | 测试污染状态 | 自动化验收使用独立临时状态库或明确清理测试记录 |

## 8. 回滚方式

- 开发在独立 `codex/v1.1` 分支和独立工作树进行，`main` 保持不动。
- 提交按“文档基线、核心功能、性能、视觉与响应式、验收”拆分。
- 需要回滚时切回 `main` 即恢复 v1.0；不删除用户数据、不重写历史。
- 数据库结构变更必须向后兼容；如新增列或表，旧版本忽略它们。禁止破坏性迁移。
- 不执行 `git reset --hard`、不覆盖主工作区、不删除 zer0share 数据。
